## Existing repairs and architecture found

- `VelvetLeanCacheWriter` already snapshots/coalesces persistent stats writes; retained unchanged.
- `VelvetLeanWidgetSupport` and Dynamic Widget integration retained unchanged.
- `VelvetPikaAuth` already reads `glide/pika-api-key.txt`, attaches X-Api-Key only to Pika HTTPS, and maps QUADS to QUAD. Native HTTP transport already uses 4.5/8 second timeouts, no redirects and a 1 MiB cap. These protections are retained and strengthened, not replaced with ChuStatsu's client.
- `PikaApiClient` is leaderboard-first, asynchronous, priority scheduled, deduplicated and revisioned, with stale results, cancellation, global cooldown, adaptive pacing, profile hydration and persistent cache. Existing automatic requests were queue-gated, but manual commands could bypass admission; the underlying PriorityBlockingQueue was unbounded. Profile executor queue/cache were unbounded and queued profile work could outlive cache clears. New bounds/epoch checks address those concrete gaps.
- Historical JSON multi-catch VerifyError is repaired in this exact baseline: 285 inherited Scout/module/screenshot classes pass Java 8 verification before modification. The new build preserves the json method's original instructions and recomputes frames with actual hierarchy information; it never uses a blanket Object fallback for exception merges.
- `ScreenshotManager` no longer bulk-decodes images in its constructor, but still reads deletion metadata, lists the directory synchronously and deletes named screenshots. `LazyScreenshotLoader` rescans on the calling thread every 1.5 seconds while the gallery is rendered. `AssetManager.loadImage(File)` decodes/uploads synchronously, caches by basename without eviction, and leaves STB image allocations unfreed. Constructor discovery/deletion is removed; indexing and decoding become lazy background operations with bounded owner-thread uploads/eviction.
- Screenshot gallery draws only visible thumbnails plus the selected image, so preserving that interface allows a narrow image-cache patch. Original files are never resized or overwritten.
- `ScoutTable` already caches formatted cell content within snapshots but repeatedly measures text during periodic rebuilds and computes vertical glyph bounds/allocates float arrays during drawing. New context/font/size/text LRUs cache those measurements without allocating lookup keys on hits.
- `Scout105Runtime` and `Velvet2Settings` property mirrors wrote synchronously whenever changed, including repeated slider updates. They now snapshot on change and coalesce atomic writes after 500 ms idle, preserving unknown keys and escaped Unicode. Core profile/configuration classes are otherwise retained.
- Existing independent HUD/TAB settings, scene layouts, social/party inference, history, session deltas, player notes/watchlists, threats, queue insights, module/input machinery and native fonts were identified. This is a binary-baseline patch workflow; no decompiled whole-client rebuild or Gradle replacement is used.
- Diagnostic frames show Discord `IPCClient.close()` null dereference. Its boolean guard is defective; simply reversing that branch would leak connected pipes. The patch instead checks the actual pipe/status, retains IOException handling, closes connected pipes, and makes uninitialized/repeated close safe. Both paths have mocked IPC tests.

## Startup and native dependencies

Discord statistics, update/news/changelog and blacklist fetches already dispatch background work; their existing helper has connect/read timeouts. No unsupported claim that these HTTP calls block the startup thread is made. Custom cape preparation still performs synchronous local image work. Font/NanoVG context/resource-pack initialization still requires real startup timing before more invasive changes; startup checkpoints now expose the intervals. The collection reports nine screenshots and 76 files in the library backup area; those backup binaries and images were not uploaded. A complete historical patch provenance cannot be reconstructed from the current JAR alone.

The JAR embeds LWJGL 3 system/NanoVG/STB/Yoga/Zstd native support, while vanilla/OptiFine use LWJGL 2 and JInput. Existing `GlideTweaker.unlockLwjgl()` removes the broad org.lwjgl exclusion and `VelvetLwjglCompat.configure()` restores narrow parent delegation for legacy OpenGL/OpenAL/input/util and selected root classes. This is a deliberate mixed-loader setup, not a reason to strip native classes. Both compatibility classes, the transformer, native resources, shared launcher dependencies and existing OptiFine configuration remain byte-identical. The new package copies no replacement native libraries. Byte identity and offline descriptors do not prove native initialization on the user's driver; that remains a local test.

CFR 0.152 from Maven Central was checksum verified and used only for private analysis. Decompiled third-party client code is not published. ChuStatsu v1.2.0 was studied at commit `26a3d83c78d14322dd211254bdb33e7dae984d5a`; no ARR Java or render assets are redistributed. Poppins is independently licensed and includes its OFL notice.

## Overhaul3 targeted follow-up

The source collector's version/library summaries were inspected again: the client uses LaunchWrapper/GlideTweaker, the exact Lean coordinate, LaunchWrapper 1.12, ASM and Optifine, with a vanilla parent library set. Full source version JSON/download fields are not in the privacy-filtered upload. The installer reads local JSON, validates the exact baseline/MC JAR, preserves inherited dependency metadata, replaces only the custom library coordinate/metadata and explicitly selects the verified game JAR. Overhaul2's invented libraries.minecraft.net custom URL is removed; artifact and legacy repository URLs are empty, with actual local path/SHA-1/size. Offline fixture tests do not certify real launcher repair behavior.

The 466/659 ns historical harness was short, allocated roster copies and included a volatile sink on every call. It did not isolate layout/rendering or show that a real game regression occurred. Inspection confirmed avoidable default copies plus number parsing of sentinel strings in per-row render controls. The warmed forked experiment and allocation counters isolate those mechanisms; see PERFORMANCE.md and preparation-comparison.json. Explicit sorts still own mutable copies, native config toggles are checked correctly, and original input order is not changed.

The native onTick null-table condition previously forced a model rebuild every tick when TAB was disabled. The guarded transform now tests missing *visible* TAB/HUD tables, preserving the native five-tick cadence/history/session updates otherwise. No networking/player collection/gameplay logic is suppressed. Head rendering contained a native image-size query writing into two new arrays which were immediately discarded; only that exact 19-instruction producer/query sequence is removed, leaving cached skin handles, draw calls and ownership unchanged.

Show/hide transitions are independently implemented using pure Java 8 state, render-owner NanoVG save/alpha/restore, existing valid tables and native world/scope guards. No copy of the ARR reference renderer/shader code is used. Shader blur/framebuffer and real 3D head mesh work is deferred pending graphics validation. Existing lazy screenshot, cape preload, QUAD/auth, JSON verification repair and mixed-native/classloader paths are retained.
