# Overhaul3 local acceptance and comparison

The supplied scripts were exercised using PowerShell 7.4 on Linux and actual Java 8. Windows cmd.exe, Windows PowerShell 5.1, the official launcher and Minecraft/native rendering were not executed in the development environment. Treat this build as a release candidate until completing these checks.

1. Close Minecraft and the launcher. Run INSTALL-WINDOWS.bat and VERIFY-INSTALLATION.bat. Installation is offline and side by side; do not delete the original client or previous Lean versions. Create a new launcher installation selecting **VelvetG-Lean-Overhaul3**, the existing game directory, and a maintained Java 8 runtime.
2. Run TEST-OVERHAUL3-WINDOWS.bat. This verifies the package, original/backup, installed patch, local-only library path/SHA-1/size, Java version and the actual installed mode normalizer. It does not launch the game or contact the network by default. The console/report distinguishes PASS, PENDING, ONLINE SKIPPED and required manual checks. Exported reports contain only allowlisted numeric data and warning counts, not raw logs.
3. In the official launcher select Overhaul3 and launch with ordinary networking. Confirm it starts without attempting to replace the local Glide JAR. Close the game and run the verifier again. The custom library uses an empty URL for both local artifact and legacy repository metadata, following the local-installed-library convention; it has no invented download URL. Launchers that insist on a nonempty download URL are unsupported pending local testing. Never add a fake Mojang URL. If a repair is requested, stop and retain the original working version.
4. Launch once without network access after the launcher's normal offline requirements are satisfied. Verify that a cached local library is sufficient. Do not delete/rename the custom JAR to force repair: missing/damaged libraries must be repaired by this patch installer, not a remote URL. A missing/changed library fails offline verification; rollback refuses unknown changes.
5. Open /velvetlean. Select CUSTOM to use preserved appearance values, or Maximum FPS / Balanced / Visual. Presets do not overwrite custom animation, image, column, font or layout values. Check TAB held/released, persistent TAB, HUD hide while TAB, waiting/active contexts, headers, 1/20/40 players, column reorder, party/watchlist/friend/team/spectator formatting, nametag ABOVE/BESIDE, and existing Dynamic Widget/Violet/SnapTap controls. The existing native HUD and API caps must also be set to 40 for the 40-row case.
6. Optional transitions: set tabHideAnimation or hudHideAnimation to FADE/SLIDE/ZOOM/BOUNCE/POP and set ShowAnimation independently. Test rapid key reversal and context/world changes. Whole-table tails are allowed only while native scope/world/module guards permit them; disconnects, GUI changes and disabled contexts clear or stop them. HUD hide continuation is provided for the native hide-while-TAB condition. Shader blur/true 3D head meshes are not implemented; do not mistake the retained hat layer for those effects.
7. Test the gallery with no images, then hundreds of existing images. Check corrupt files, fast scrolling and revisits; confirm original screenshots remain byte-identical. Use Open to view originals. Verify native cache counts settle; no actual GPU lifecycle test was possible in the cloud.
8. For Pika, use the existing local key or masked entry. Automatic /apikey remains opt-in. Test a genuine server key response, rejected key recovery, reconnect and /stats. To perform one independent Java-runtime authentication check: **TEST-OVERHAUL3-WINDOWS.bat -Online -Player YourName**. It reads glide/pika-api-key.txt locally, sends X-Api-Key only to HTTPS stats.pika-network.net, requests MONTHLY/QUAD, follows no redirects and makes no retries. Keys are never command arguments. Only HTTP status is reported. A 200 validates that request/runtime; it does not prove the chat-capture/live rendering paths passed. Avoid rerunning on 429 until the server cooldown expires.
9. After startup wait at least one second for the asynchronous timeline write, then run the smoke kit to collect config/velvetg-startup.properties as a numeric CSV. It spans instrumented Minecraft.startGame splash checkpoints and Glide/module initialization, not launcher authentication/downloads, and intervals include all intervening work. No checkpoint can attribute exclusive GPU time. A crash/stall before completion may leave the previous timeline; check its local file modification time and repeat with a fresh launch.
10. Enable profiler, warm up the game, follow a repeatable scene/route, then Export in /velvetlean immediately after the measured interval. The last 4096 CPU-observed client-loop intervals are exported to config/velvetg-frame-samples.csv; the smoke kit computes their mean/P95/P99 and slowest-1%-mean FPS equivalent. These are not GPU timings. Exports are not reset automatically; collect freshly and check timestamps for every run.
11. Compare Overhaul2 and Overhaul3 using the same Java 8, heap/GC flags, 1280x720 resolution, view distance/video settings, resource packs, FPS cap, world/route/player count and warmup. Alternate versions for at least five runs each, using three or more cold starts separately. Keep a baseline/Overhaul2 and candidate folder for each run. Use RECORD-BENCHMARK.ps1 -ProcessId <game PID> -Label baseline (or patched) -DurationSeconds 60 for process CPU/memory/thread CSV. No process command lines are collected. Overhaul2 has summary profiler data but no raw interval CSV unless separately instrumented; do not compare its FPS counter to Overhaul3 P99. Use the same trusted frame recorder for both if raw baseline frames are needed.
12. Repeat visual tests with Maximum FPS on/off and images/fonts/animations on/off. Check controls and advanced history/session/watchlist behavior before choosing the candidate as your normal installation. Save any reproducible failure details locally; the kit intentionally exports only exception/warning counts, so inspect logs on your PC for stack traces and redact secrets before sharing.
13. To remove the candidate, close Minecraft and run RESTORE-BACKUP.bat, then select the original/Overhaul2 version. Backups, settings, profiles and screenshots remain. Interrupted installation/removal is recoverable on the next invocation if journaled files still match; changed files are retained and require investigation. No unknown baseline is overwritten.

For a clean measurement window without opening a GUI, use `/velvetlean profile start`, follow the scene/route, then `/velvetlean profile stop` to freeze and export. `/velvetlean profile export` exports without stopping. These commands are handled locally; they do not change the saved profiler preference.
